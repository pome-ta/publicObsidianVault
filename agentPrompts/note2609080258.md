Tone.jsを使ったライブコーディング（音楽用リアルタイムコード編集）システムを実装したい。  
前提と要件は以下の通り:  
  
1. DOM上のボタン/スライダーではなく、コードを書き換えて実行中の音を変える形式にしたい。  
2. ユーザーが「切り替え」を指示しても即時反映せず、`Tone.Transport`のテンポを保ったまま、  
   次の拍/小節などの「いい感じのタイミング」で変化を適用したい  
   （`Tone.getTransport().schedule(callback, "@1m")` のような量子化スケジューリングを使う）。  
3. ユーザーの「切り替え指示」は`Tone.Emitter` のようなイベントバスで発火・購読し、  
   「指示イベントの発火」と「実際の音の適用（quantizeされたTransport.schedule内）」を分離する。  
4. `Tone.Synth` /`Tone.Sequence` / `Tone.FMSynth` などのインスタンスは、  
   評価スコープをまたいで保持する「永続的な箱」（グローバル/モジュールスコープのレジストリオブジェクトやMap）  
   に保持し、切り替え時に新しいインスタンスを作って古いものを`dispose()` する。  
   （`Sequence` の `subdivision` はコンストラクタでしか設定できないため、粒度を変える場合は新規インスタンスにスワップが必要）  
5. 音色/パターンを切り替える際、`Tone.CrossFade` の`fade(Signal)` を `rampTo()` でランプすることで、  
   新旧の音源をぶつ切りでなく滑らかに移行させたい。  
  
これまでの会話で「`Tone.Emitter` + `Transport.schedule("@1m")` + レジストリパターン + `CrossFade`」  
を組み合わせた統合コード例を作成済み。この続きから設計/実装を深掘りしたい。
